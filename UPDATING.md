# Как обновляется это портфолио

**Источник истины — закрытая монорепа `vlm-course`. Этот репозиторий —
её зеркало по выбранным пакетам плюс четыре собственных файла.** 416
файлов зеркалятся 1:1 (тот же путь, тот же байт в байт); README,
`HONESTY.md`, `Makefile`, `pyproject.toml`, CI и лицензия принадлежат
портфолио. Ручная синхронизация такого объёма разъезжается за месяц —
поэтому она не ручная.

## Что откуда

| Здесь | Откуда | Кто владеет |
|---|---|---|
| `assistant/ … tracking/`, `src/`, `config/`, `k3s/`, `ros2_ws/`, `docs/` — каталоги целиком | тот же путь в `vlm-course` | источник |
| `scripts/*.py`, `tests/*.py` — **пофайлово** (в источнике их больше) | тот же путь | источник |
| `requirements*.txt`, `Dockerfile.jetson`, `docker-compose.jetson.yml` | тот же путь | источник |
| `README.md`, `HONESTY.md`, `Makefile`, `pyproject.toml`, `requirements-ci-core.txt`, `.github/`, `LICENSE`, `.portfolio/`, `UPDATING.md` | — | портфолио |

Полный список — [`.portfolio/manifest.yaml`](.portfolio/manifest.yaml).
Файл зеркалится, но правится здесь → он в секции `patched` манифеста:
`sync` его не перезапишет, но будет напоминать, что правку надо вернуть
в источник. Сейчас там один файл
(`quantization/tests/test_script_02_export_onnx.py`, `importorskip("torch")`,
03.11.2026) — вернуть в `vlm-course` и убрать из `patched`.

## Триггеры обновления

- В `vlm-course` исправлен баг или изменён модуль в зеркалируемом пакете.
- Реальный прогон (Jetson, dev-машина) дал новую запись в журнал
  верификации источника (`course/PROGRESS.md`, `course/STATUS-BOARD.md`,
  `course/FAILURE-TABLES.md`) по коду, который здесь есть →
  строка в `HONESTY.md`.
- Из источника решено вынести новый пакет (новый трек вакансий).

Без триггеров — раз в месяц `check`.

## Процедура

```bash
# источник рядом (../vlm-course) или PORTFOLIO_SOURCE=/path/to/vlm-course
python .portfolio/sync.py check          # 1. дрейф: изменено / новое / удалено / patched
python .portfolio/sync.py apply          # 2. скопировать; --prune — ещё и удалить то, чего в источнике больше нет
                                         #    остановится, если в копируемом есть цены/контакты/заимствованные тексты
python .portfolio/sync.py verify         # 3. джоба core локально (без torch — см. README, «Как проверялось»)
# 4. HONESTY.md: новая строка на каждый реальный баг/проверку по перенесённому коду. Не гипотезы.
# 5. README: если изменился состав пакета или команда запуска — поправить строку трека.
# 6. Коммит: заголовок = что изменилось по существу. Push. Обе джобы CI зелёные.
```

Проверка полного стека (джоба `ml`) локально дорогая — её делает CI.
Если `verify` зелёный, а `ml` упал — почти наверняка тест утверждает
что-то про среду (нет torch / нет сети до HF), а не про код; см.
комментарии в `.github/workflows/ci.yml`.

## Добавление нового пакета (трека)

1. В `manifest.yaml` → `mirror:` добавить каталог (целиком) или файлы.
2. `apply`, затем `verify`. Если пакету нужен torch — добавить его шаг в
   джобу `ml`, иначе в `core`; команду теста — в `verify:` манифеста.
3. В README — строка в таблице трека: *для каких вакансий*, *что внутри*,
   *команда запуска*. Не больше.
4. В `HONESTY.md` — раздел с реальными прогонами этого пакета. Если
   прогонов на реальном окружении не было — так и написать («тесты
   проходят в песочнице; на физическом Jetson не проверено»), как сделано
   для `quantization/` и капстоуна.

## Формат строки `HONESTY.md`

```
- **<Пакет> (`путь/`)**: <где прогнано: песочница / dev-машина / Jetson> —
  <что сломалось, дословно или близко> → <причина> → <фикс>.
  <Что ОСТАЛОСЬ непроверенным, если осталось.>
```

Запись «прогнано, новых находок нет» — тоже строка, не тишина.

## Что сюда не попадает никогда

Курс (`course/`), недели, `outputs/`, бэкапы, бизнес-документы
(`BUSINESS-*`, `*-MARKETING-*`, `DAILY-PROMPTS`), веса моделей
(`*.onnx`, `*.engine`, `*.pt` — исключены манифестом), контакты и цены.
Манифест проверяет regex'ом, но это страховка: перед `apply` новых
каталогов — посмотреть глазами.
