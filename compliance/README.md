# compliance/ — неделя 21: security и лицензионный аудит

Системная проверка лицензионных (copyleft) и ИБ-рисков всего стека
зависимостей — не разовая находка по одному случаю (как `AGPL-3.0`
`ultralytics`/YOLOv8 в [`course/OPERATION-CARDS.md`](../course/OPERATION-CARDS.md)'s
`ДН-03`), а повторяемый автоматический прогон.

**Эта неделя частично про процесс/чеклист, не только код** — и это
нормально: не каждая неделя курса обязана заканчиваться новым сервисом
на Jetson (см. `ROADMAP-WEEKS-13-24.md`'s явную оговорку для этой
недели).

## Что внутри

- `sbom.py` — `generate_sbom(requirements_files)`: CycloneDX-образный
  JSON по всем `requirements*.txt` репозитория, резолвя пакеты через
  stdlib `importlib.metadata` (та же информация, что читает
  `pip-licenses`, без новой зависимости для одного отчёта). Пакет, не
  установленный в ТЕКУЩЕМ окружении — явно `unresolved`, не угадывается.
- `license_audit.py` — `classify_license(license_name)`: 4 категории
  (`permissive`/`copyleft`/`commercial_restricted`/`unknown`) по
  рукописному списку известных SPDX-идентификаторов. НИКОГДА не
  пытается распарсить длинный блок текста (см. «Почему не угадываем»
  ниже) — явный `unknown`.
- `checklist.py` — структурированный ИБ-чеклист: 5 пунктов из
  существующего опросника `course/modules/ot-integration-for-cv-engineer/
  day02-ot-it-network-segmentation.md`'s раздела 4 + 6 пунктов из
  `course/TECH-DEBT.md`'s раздела F — каждый с реальным статусом
  (`closed`/`open`/`not_applicable`) и обоснованием, не выдуманный
  список.
- `adversarial_demo.py` — один adversarial-кейс (физическая наклейка
  поверх реального маркера дефекта недели 04's `StubDetector`) + одна
  мера защиты (`tracking.smoothing.VerdictSmoother`, неделя 13) с
  измеренным до/после эффектом.
- `scripts/run_license_audit.py` — весь деливерабл одной командой: SBOM
  → лицензионный аудит (подтверждает `ultralytics`/`AGPL-3.0`
  автоматически) → ИБ-чеклист → adversarial-демо.

## Почему не угадываем (classify_license)

Реальные установленные пакеты в этом окружении кладут лицензию в
метаданные ТРЕМЯ разными способами, подтверждено эмпирически:
- `torch` — через PEP 639 `License-Expression`: `"Apache-2.0 AND Apache-
  2.0 WITH LLVM-exception AND BSD-2-Clause AND BSD-3-Clause AND BSL-1.0
  AND MIT"` (комбинированное SPDX-выражение, включая `WITH`-исключение).
- `transformers` — через поле `License`: `"Apache 2.0 License"` (свободный
  текст, не SPDX ID).
- `numpy`/`scipy`/`matplotlib`/`onnxscript` — через поле `License`: **вся
  лицензия целиком** (тысяча+ символов), не короткий идентификатор.

Попытка найти подстроку типа `"GPL"` внутри тысячи символов
юридического текста рискует ложным совпадением (например, упоминанием
в отказе от ответственности) куда больше, чем пропущенной реальной
классификацией — поэтому `classify_license` явно возвращает `unknown`
для текста длиннее `_MAX_CLASSIFIABLE_LENGTH` (200 символов), вместо
попытки его распарсить. В РЕАЛЬНОМ прогоне против этого репозитория
(`make demo`) `numpy`/`scipy`/`matplotlib`/`onnxscript` именно поэтому
попадают в `unknown` — это честный результат, не недосмотр.

## Почему ultralytics/AGPL-3.0 — не просто повторение прошлой находки

`compliance/tests/test_sbom.py::test_generate_sbom_real_ultralytics_is_agpl_in_this_environment`
подтверждает факт (`importlib.metadata.distribution("ultralytics").metadata["License"] ==
"AGPL-3.0"`) в ЭТОМ окружении, и `scripts/run_license_audit.py`'s
`main()` явно печатает, нашёл ли автоматический прогон `ultralytics` и
с каким риском. Реальный прогон (`make demo`) подтверждает:
`ultralytics: license='AGPL-3.0', risk='copyleft'` — обнаружено
автоматически, не подставлено из прошлой находки недели 07.

## Adversarial-кейс: физическая наклейка над маркером дефекта

Не research-уровня атака — то, что реально проверяют при приёмке
(`ОБ-04`): физическое перекрытие части видимого дефекта. Используется
РЕАЛЬНЫЙ алгоритм `pipeline/scripts/04_detect.py`'s `StubDetector`
(загружен по пути напрямую, т.к. имя файла с цифры нельзя импортировать
обычным `import`), не переизобретённая логика.

Сценарий (`DEFAULT_PATCH_COVERAGES = (0.70, 0.95, 1.00, 0.80, 0.70)`) —
детерминированный, НЕ случайный: имитирует наклейку, чьё положение
колеблется от кадра к кадру (вибрация/параллакс), а не идеально стабильно
перекрывающую дефект каждый раз. Реально измерено (`make demo`):

- **До защиты**: 2 из 5 кадров (coverage 0.95 и 1.00) реально обманывают
  `StubDetector` на уровне одного кадра — `raw_false_negative_rate=0.40`.
- **После защиты** (`VerdictSmoother(window_size=5)`, majority vote по
  треку): финальный вердикт трека — `"defect"` (ПРАВИЛЬНО), несмотря на
  40% обманутых кадров — `defense_recovered_correct_verdict=True`.

**Честный предел защиты, не скрытый**: majority vote — это буквально
«что чаще» за окно. Если атакующий надёжно обманывает БОЛЬШИНСТВО
кадров окна (например, 3 из 5), сглаживание тоже выдаст неверный
итоговый вердикт — это не универсальная защита, а поднятие порога
атаки с «обмани один кадр» до «обмани большинство окна». Тест
`test_defense_has_a_real_limit_when_most_frames_are_successfully_attacked`
явно демонстрирует этот предел, а не прячет его.

## Чеклист ИБ приёмки

11 пунктов (`OT-1`…`OT-5` из опросника OT-интеграции, `SEC-1`…`SEC-6` из
`TECH-DEBT.md`'s раздела F). В реальном прогоне против этого репозитория
сегодня: **1 closed, 9 open, 1 not_applicable** — честное отражение
текущего состояния, не «всё зелёное для демо». `OT-1`…`OT-5` — пункты
про физическое устройство/сеть, которые по определению нельзя закрыть
без реальной площадки; `SEC-1` закрыт реальным кодовым митигейшном
(`DeployPathConflictError`); остальные `SEC-*` — открытые, уже
задокументированные в `TECH-DEBT.md` риски.

## Honesty note

**Проверено по-настоящему (не только написано)**:
- `generate_sbom`/`classify_license` — реально резолвят установленные в
  ЭТОМ окружении пакеты через `importlib.metadata` (не мок), включая
  настоящий `torch`'s PEP 639 `License-Expression` с `WITH`-исключением
  и настоящую полную лицензию `numpy` (слишком длинная для классификации
  — корректно `unknown`, не угадано).
- `ultralytics`/`AGPL-3.0` — подтверждено автоматическим прогоном против
  реального установленного пакета, не захардкожено.
- `adversarial_demo.py` — реально прогоняет `pipeline/scripts/
  04_detect.py`'s настоящий `StubDetector` на реально сгенерированных
  изображениях и настоящий `tracking.smoothing.VerdictSmoother` — числа
  в этом README измерены (`make demo`), не оценены.
- `checklist.py`'s все 11 пунктов — реальные, уже задокументированные
  находки этого репозитория (не придуманные для недели), с явной
  ссылкой на источник каждого.

**Не сделано в этом проходе**:
- SBOM не покрывает пакеты, предустановленные в JetPack и НЕ ставящиеся
  через pip (например, системный `TensorRT`/`CUDA` из образа JetPack) —
  `requirements-jetson.txt` перечисляет только pip-зависимости; у этого
  репозитория физического Jetson нет, чтобы это проверить реально.
- `classify_license`'s список известных лицензий — рукописный и
  умышленно небольшой (покрывает то, что РЕАЛЬНО встретилось в этом
  стеке); новая, не встреченная лицензия корректно попадёт в `unknown`,
  а не в неправильную категорию — это намеренное поведение, не пробел,
  но список не претендует на полноту каждой лицензии в мире.
- `OT-1`…`OT-5` — чеклист не автоматизирован и не может быть: это
  проверки против физического устройства/сети конкретной площадки, не
  то, что код может подтвердить сам по себе.
- Второй adversarial-кейс (засветка камеры, из `P21.3`'s ресёрча) —
  не реализован в этом проходе; `adversarial_demo.py` документирует ОДНУ
  атаку+защиту, осознанно не пытаясь закрыть всё (см. roadmap недели 21).
